# 报文解析生成工具

CIIS / RMSCI 报文解析与生成工具。单文件 HTML，双击即用，无需安装、无需联网。

## 当前版本

**V1.7.0** —— `报文解析生成工具V1.7.html`

`报文解析生成工具V1.6.html`、V1.5、V1.4（含 1.4.1 的拆壳修复）与 V1.3 / V1.2 保留在此，用于回滚。

## 功能

- **字段报文**：从 docx / xlsx 字段文档导入字段定义，勾选需要的字段、逐项填值，导出 JSON / Key=Value 报文
- **报文协议库**（V1.3.0 新增）：同时保存多份字段定义，顶栏下拉切换，每份协议独立保存已填写的值
- **磁盘备份**（V1.4.0 新增）：把协议库自动写进一个真实 json 文件，随工具一起拷到别的电脑即可恢复
- **宽容拆壳**（V1.4.1 新增）：粘贴 `["{\"tradeInfo\":…}"]`、整段字符串、字符串套数组、从日志复制的多层转义都能解析，导出可原样还原
- **从报文建协议**（V1.5.0 新增）：粘贴任何一份新报文，一键按它的真实结构新建独立协议（对象分组 + 数组表格），不再硬往内置协议里凑
- **字段名称可编辑 / 可批量补**（V1.6.0 新增）：名称列直接手写；也可粘贴字段说明或导入 docx / xlsx，按字段标识自动匹配填名
- **接口调用**（V1.7.0 新增）：把填好的报文直接发给本机 CIIS / RMSCI 小工具（9988），返回就地展示；环境可多套保存
- **XML 报文**：粘贴 XML 解析出所有带内容的标签，按标签名筛选、改值后重新导出
- **校验提示**：必填缺失、枚举越界、长度超限、金额位数、日期格式、债券代码重复 / 沪深混券等

## 粘贴的报文带外壳怎么办

接口返回、日志里复制出来的报文经常被包了几层，工具会逐层剥到真实报文对象：

| 粘贴形态 | 处理 |
|---|---|
| `["{\"tradeInfo\":…}"]` | 剥：数组(1) → 字符串 |
| `"{\"tradeInfo\":…}"` | 剥：字符串 |
| `"[{\"tradeInfo\":…}]"` | 剥：字符串 → 数组(1) |
| `"[\"{\\\"tradeInfo\\\"…}]"`（多层转义） | 逐层去转义后剥，最多 8 层 |
| `[{…},{…}]` 多条 | 只导入第 1 条，提示里说明条数 |
| `[]` / `[null]` / `[1074]` | 明确报错：空数组 / 首项是 null / 首项是数字 |

导出时勾选 **「带回原始外层包装」**，会按粘贴时的形态原样还原（`["{…}"]` 就还 `["{…}"]`）；
不勾则导出纯净的 `{…}`。外层结构会随协议一起存进浏览器，切换协议、刷新页面都还在。

**保真规则**：匹配不到协议的数组 / 对象字段（如 `exchangeBondList`、`requestInfo`）按原结构写出，
不会被压成字符串；`isCoupon:true` 导出 `true`、`dealer:1074` 导出 `1074`，不会一律变成字符串。
这类结构化字段在「额外字段」里显示为可展开的 `数组 N 项` / `对象 N 字段`，不参与「映射到标准字段」。

## 用粘贴的报文新建协议（V1.5.0）

内置协议是 RMSCI 协议回购的字段体系。当你手上的报文是**别的业务**（例如交易所回购 `REPO_EXCHANGE`），
字段名与内置协议对不上，硬导入只会掉进「额外字段」，没法用表格填写。这时用：

1. 把报文粘到「① 粘贴报文」，点 **「＋建为协议」**；
2. 弹窗预览自动反推出的结构（几个对象、几个数组、多少字段），改个协议名；
3. 点「新建协议」→ 生成一份**独立协议**，报文里的值直接填好并勾选，改完即可导出。

反推规则：

| 报文里的东西 | 变成 |
|---|---|
| 根节点的标量（`dealer`） | 根字段卡片 |
| 对象（`tradeInfo`、`requestInfo`） | 各自一张对象卡片，字段键名显示短名 |
| 数组（`tradeInfo.exchangeBondList`） | 一张表格，数组元素是行、元素里的键是列 |
| 数组元素里的对象 / 数组 | 该列按 JSON 原样保存与导出，不丢结构 |
| 标量数组（`"ids":[1,2]`） | 一个字段，值就是 JSON，导出仍是数组 |
| 类型 | 自动识别 `Integer` / `BigDecimal` / `Boolean` / `String`，`true`、`1074` 原样保真 |

树形协议下「扁平结构 / 嵌套 tradeInfo」切换会自动隐藏——结构由协议本身决定，导出严格按报文层级还原。

## 接口调用：改完报文直接发（V1.7.0）

把「本机小工具」（`D:\接口工具\CIIS-Tester\jetty-runner` / `D:\接口工具\jetty-runner\jetty-runner`，都是 jetty + `tester.war`，9988 端口）的发送能力并进工具里：报文改完，一键作为 `params` 发出去，返回就地看。

### 为什么必须从 9988 打开

两个 `tester.war` 的响应里**没有** `Access-Control-Allow-Origin`。所以：

| 打开方式 | 结果 |
|---|---|
| 双击 html（`file://`） | 请求发得出去，但浏览器把返回扣掉，读不到 |
| `http://127.0.0.1:9988/msgparse/` | 与 `/tester/api` 同源，返回正常读取 ✅ |

首次使用先双击 **`安装到小工具.bat`**，它会把本页复制成两个工具目录下的 `webapps\msgparse\index.html`（jetty 会把 `webapps` 下的目录部署成站点，已实测）。之后：

1. 双击 `9988.bat` 启动小工具（CIIS 或 RMSCI，二选一，都是 9988）；
2. 浏览器打开 `http://127.0.0.1:9988/msgparse/`；
3. **起的是哪个服务，就发到哪个服务**——接口地址永远跟随当前页面，不用配。

> **`安装到小工具.bat` 必须是 ANSI / GBK 编码 + CRLF 换行**。用 VS Code、记事本等把它另存成 UTF-8 后双击会**一闪就退**（cmd 按 GBK 读 UTF-8 中文会乱码、长行被切断），改完编码存回 ANSI 即可。脚本跑完会自动 `pause` 停住，看到「请按任意键继续」说明没闪退。
> 9988 还开着时复制会被拒（Windows 文件占用），脚本会明确报 `[失败] … 多半是 9988.bat 还在跑`，关掉黑窗口再跑一次即可。

### 怎么发

1. 「字段报文」页填好报文 → 点导出区的 **「发送到接口 →」**（或到「接口调用」页点 **「← 取当前报文」**），参数自动带过去；
2. 选服务、方法（也可手填服务名与自定义方法）；
3. 点 **「发送报文」**。

发送时会**先自动 connect 一次**，再发 `/send`。原因：小工具服务端的 `CCIClient` 是会话级的，没连过或上次连接失败被关掉时，直接 `/send` 只会回一句「CCIClient 已经被关闭」，根本没法排查。自动连接后，连不上就直接告诉你真实原因（登录失败 / 端口不通），报文不会白发。

### 环境（多套保存）

| 字段 | 说明 |
|---|---|
| 环境名 | 下拉里显示，自己起，比如「RMS 172.19.223.74」 |
| 服务地址 / 服务端口 | 被测系统，CIIS 常见 `8003`，RMSCI 常见 `8010` |
| 登录用户 / 登录密码 | 密码以 `b64:` 混淆存本地（不是加密，防顺手看见） |
| 接口类型 | CIIS（2 个服务 + 通用方法）/ RMSCI（28 个服务） |
| 压缩传输 | 只在「测试连接」时带给 `/connect` |

改动即时自动保存，切环境各存各的；「新建 / 另存为 / 删除」管理多套。

### ⚠️ 换到 9988 打开后数据是空的？

浏览器**按站点隔离存储**：`file://` 和 `http://127.0.0.1:9988` 是两套 localStorage。以前双击用着的一切（协议库、填写值、环境）在 9988 页面里读不到，这是浏览器行为，不是丢数据。

迁移一次即可：在 9988 页面顶栏点 **「恢复」** 选你的备份 json（或「导入协议」逐个导），之后就一直用这个地址。

## 字段名称怎么补（V1.6.0）

按报文新建的协议，字段只有英文 key，名称列是空的（报文里本来就没有中文名）。三条路，随便用哪条：

1. **直接手写**：名称列就是输入框，点进去改，改完自动存进协议（不进报文，只影响界面显示）。
2. **粘贴字段说明**：点右侧 **「补充字段名称」**，把需求文档 / 接口文档里的字段说明复制粘贴进去，边贴边出预览。
3. **导入文档**：同一个弹窗里点「导入 docx / 导入 xlsx」，只补名称，**不动**协议结构与已填的值。

粘贴内容不挑格式，一行一个字段即可：

```
dealer	外部接口本方交易员	String	否
dealer：外部接口本方交易员
dealer=外部接口本方交易员
| dealer | 外部接口本方交易员 | String | 否 |
- dealer 外部接口本方交易员，仅供展示
```

制表符表格、竖线表格、冒号、等号、空格都能识别；从 Word 表格复制时单元格内的换行会把名称挤到下一行，工具会把下一行接回上一行；纯类型（`String`）、必填标记（`是/否`）、纯数字会被跳过，不当作名称。

匹配规则与安全边界：

| 情况 | 处理 |
|---|---|
| 字段说明写全路径 `tradeInfo.dealer` | 精确匹配该字段 |
| 只写短名 `dealer` | 按末段匹配；多个层级都有同名字段时只写**最浅**的那个，并标「多义」 |
| 目标字段已有名称 | 默认保留，勾 **「覆盖已填名称」** 才强制刷新 |
| 名称与现值相同 | 标「已一致」，不重复写 |
| 字段说明里有、报文里没有的字段 | 只列在「未匹配」里，**不会**凭空加字段 |
| 数组表格的列名 | 也能匹配；列头名称点一下就能单独改 |

预览逐条列出「字段 → 当前名称 → 将写入的名称 → 状态」，确认无误再点「应用名称」（或 Ctrl+Enter）。

## 报文协议怎么用

| 操作 | 说明 |
|---|---|
| ＋建为协议 | 按粘贴报文的真实结构新建一份独立协议，并带入报文里的值（V1.5.0） |
| 补充字段名称 | 粘贴字段说明 / 导入 docx、xlsx，按字段标识自动填名称列（V1.6.0） |
| 导入字段文档 / 导入Excel | 解析后弹出对话框，可选「新建协议」或「覆盖当前协议」 |
| 顶栏下拉 | 切换协议，字段定义与已填值一并切换，各协议互不影响 |
| 复制为 | 以当前协议为模板新建一份，填写值清空 |
| 重命名 / 删除 | 删除不可恢复，删前建议先导出 |
| 导出协议 | 导出当前一条协议为 json（含字段定义 + 当前填写值） |
| 导入协议 | 从 json 恢复协议，重名自动加 `(2)`；也能直接读「导出全部」的备份文件 |
| 导出全部 | 把所有协议打包成一个 json 下载，任何浏览器都可用 |
| 备份到… | 选一个磁盘上的 json 文件作为备份目标（建议选本工具所在目录），之后自动写入 |
| 备份 / Ctrl+S | 立即写入一次，不用等自动备份 |
| 恢复 | 从备份文件读回，先预览再选「整体替换」或「合并」 |

## 磁盘备份怎么用

1. 点顶栏 **「备份到…」**，在弹框里选到**本工具所在的文件夹**，文件名默认 `报文协议库_备份.json`，保存。
2. 顶栏状态点变绿并显示 `已备份 15:42 · 6 份协议`，此后每次改动会在 1.5 秒内自动写入该文件（不会打断填写）。
3. 换电脑：把 `报文解析生成工具V1.7.html` + `报文协议库_备份.json` 一起拷过去，打开后点 **「恢复」** → 选这个 json → 选「整体替换」即可。
4. 重启浏览器后写权限会退回「待确认」，顶栏变黄点，点一次 **「备份」** 授权后就恢复自动写入（同一会话内不再打扰）。

合并时同一条协议（id 相同）会按「本地 / 备份」的更新时间给默认值，也可逐条改；其余协议直接追加，不会覆盖。

**浏览器限制**：自动备份依赖 File System Access API，只有 Chrome / Edge 等 Chromium 浏览器支持。用 Firefox 或遇到浏览器禁止直接写本地文件时，顶栏会提示，此时改用「导出全部」下载 json，换电脑用「导入协议」读回，效果等同。

## 数据存放在哪

协议与填写值存在浏览器的 `localStorage`：

- `rms_repo_msg_protocols_v2` —— 协议库（V1.3.0 起）
- `rms_repo_msg_model_v1` / `rms_repo_msg_tool_v1` —— V1.2 旧 key，仅首次打开时读取并迁移
- IndexedDB `msgproto_bk_v1` —— 只存备份文件的句柄（不是数据本身），V1.4.0 起

所以：**换电脑、换浏览器、清浏览数据都会丢本地那份**。要带走请用「备份到…」+ 拷文件，或「导出全部」。

从 V1.2 升级时，旧的单份字段定义与填写值会自动迁移成一条名为「内置默认协议（V1.2 迁移）」的协议，不会丢。

- 顶栏加 备份到… / 备份 / 恢复 / 导出全部，状态点显示「已备份 15:42 · N 份协议」
- 改动后 1.5 秒防抖静默写入，不打断填写；Ctrl+S 可立即备份
- 「恢复」先弹预览：备份时间、协议数量、与本地重名的逐条列出，再选整体替换或合并
- 备份文件与单协议导出的 json 可互相识别；导出全部 = 一份文件打包所有协议
- 浏览器不支持自动备份时（如 Firefox）自动降级为只显示「导出全部」并给出提示
- 备份文件被外部改坏 / 被占用 / 被移动时只报状态，不影响正常填写与本地保存

## 已知限制

- Excel 仅支持 `.xlsx`，旧版 `.xls` 需先另存为 `.xlsx`
- 树形协议（从报文新建）用 V1.4 及更早版本打开时看不到对象/数组字段，请勿跨版本回退使用同一份数据
- 从报文反推的字段没有中文名与校验规则（报文里没有这些信息），「名称」列显示为空——用「补充字段名称」或直接手写补上（V1.6.0）
- 协议库整体占用超过约 3MB 会提示，接近浏览器 5MB 上限
- 只做协议整体的新增 / 覆盖，不做两份协议的字段级合并比对
- 名称匹配只认字段标识（全路径或末段）精确相等，不做相似度 / 拼音 / 中文名反向猜测；
  字段说明里的 key 与报文对不上（如 `dealerName` vs `dealer`）就进「未匹配」，需要手改那一行再贴
- 一次只处理一条报文：粘贴多条时只取第 1 条（提示里会写条数），没有批量拆分
- 报文数组名与协议不一致时（如报文 `exchangeBondList` vs 协议 `securityInfo`）不做别名映射，
  该字段留在「额外字段」里按原结构导出；要在表格里逐条编辑，需用「导入字段文档」建对应的协议
- 自动写盘需要 Chrome / Edge；重启浏览器后要重新授权一次
- 文件名/目录被外部移动或删除后，备份会失效，需重新「备份到…」选位置
- 接口调用必须从 `http://127.0.0.1:9988/msgparse/` 打开：两个 `tester.war` 不返回 CORS 头，双击 `file://` 时浏览器会扣掉返回（V1.7.0）
- 一个页面只能调它所在的那个小工具：CIIS 起在 9988 就调 CIIS，要测 RMSCI 就换成 RMSCI 的 9988 再开页面
- `file://` 与 `127.0.0.1:9988` 的 localStorage 互相隔离，切换地址后旧协议需要通过「恢复 / 导入」搬一次（V1.7.0）
- 返回报文超长时浏览器渲染会变慢；接口调用只做「发一条、看一条」，不做批量或并发压测
